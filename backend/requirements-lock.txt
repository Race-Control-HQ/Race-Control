# Reproducible install for CI and production images.
#
# `requirements.txt` is the human-edited floor/ceiling spec (what versions
# are acceptable); this file is the fully-resolved, exact-version snapshot
# actually installed, including transitive dependencies (fastf1 alone pulls
# in pandas/numpy/scipy/matplotlib and more). `pip install -r requirements.txt`
# with no lock gives a fresh production image whatever the resolver picks
# that day -- this file makes "what's actually running" a repository diff
# instead of a surprise.
#
# Generated against `python:3.12-slim` (the exact base image in
# backend/Dockerfile) via:
#     docker run --rm -v "$PWD/requirements.txt:/req.txt:ro" python:3.12-slim \
#       sh -c "pip install --no-cache-dir -r /req.txt pytest httpx && pip freeze"
# `pytest`/`httpx` are included because CI installs them alongside the app
# dependencies (see .github/workflows/backend-ci.yml) -- they are test-only,
# never imported by the running API, but locking them too keeps CI itself
# reproducible.
#
# Regenerate with the same command whenever requirements.txt changes, review
# the diff, then commit both files together. Dependabot (see
# .github/dependabot.yml) opens a PR against requirements.txt on a weekly
# cadence; regenerate this file as part of reviewing that PR.
