# Getting Support

RaceControl is a community project. Support happens in the open on GitHub.

## Where to go

| You have | Go to |
|---|---|
| A question, or an idea to talk through | [GitHub Discussions](https://github.com/Race-Control-HQ/Race-Control/discussions) |
| A bug | [Open a bug report](https://github.com/Race-Control-HQ/Race-Control/issues/new/choose) |
| A feature request | [Open a feature request](https://github.com/Race-Control-HQ/Race-Control/issues/new/choose) |
| A security vulnerability | [Report it privately](https://github.com/Race-Control-HQ/Race-Control/security/advisories/new). Do not open a public issue. See the [Security Policy](/contributing/security). |
| A code of conduct concern | [support@owl-media.co.uk](mailto:support@owl-media.co.uk) |
| A mistake in these docs | "Edit this page on GitHub" at the bottom of the page |

Search existing issues and discussions first. Someone may already have the answer.

## A good bug report

It helps a great deal if you include:

- which piece is affected: backend, iOS, Android, web app, site or docs
- what you did, what you expected and what happened instead
- the season and round, if it concerns a particular race
- the device, OS version and app version, or the browser
- for the backend, the endpoint and the response

If a number looks wrong in one app, check the same race in another client or on the [API](/api/index) directly. That tells us whether the problem is in the data or in one client.
